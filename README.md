# Сайт RemCard ICU

Одностраничный русскоязычный сайт проекта [RemCard ICU / RemCard / «Рем Карта»](https://github.com/Donkiton/rem_card) — Windows-приложения с доступным исходным кодом для процессов отделения реанимации и операционного блока.

Сайт объясняет назначение проекта, роли пользователей, модули и архитектуру, показывает реальные экраны на демонстрационных данных и честно обозначает экспериментальный статус программы.

Ссылка English в шапке ведёт к [английскому обзору](https://donkiton.github.io/rem_site/#english). В истории проекта размещён официальный значок каталога Clinicians That Code со ссылкой на карточку автора.

## Требования

- Node.js `>=22.13.0`;
- npm;
- доступ к интернету при первой установке пакетов и для получения публичных показателей GitHub.

Ошибка GitHub API не ломает страницу: вместо чисел отображается нейтральный текст.

## Локальный запуск

```powershell
npm install
npm run dev
```

Откройте адрес, который покажет команда разработки. Переменная `NEXT_PUBLIC_SITE_URL` для локальной работы не обязательна.

## Проверки и production-сборка

```powershell
npm run lint
npm run typecheck
npm run build
npm test
```

`npm test` повторно собирает проект, проверяет выбор стабильной версии и согласованность номера и ссылки релиза в готовом HTML, а также SEO-файлы.

## Публикация

Сайт публикуется по адресу [donkiton.github.io/rem_site](https://donkiton.github.io/rem_site/) через GitHub Pages. Workflow `.github/workflows/pages.yml` при изменении ветки `main` или ручном запуске:

1. устанавливает зависимости;
2. проверяет типы и код;
3. создаёт статическую Next.js-сборку в `out/`;
4. проверяет выбор стабильной версии, HTML, `robots.txt` и `sitemap.xml`;
5. публикует результат в GitHub Pages.

В pull request к `main` выполняются первые четыре шага без публикации. Запуска по расписанию нет.

GitHub Pages размещает проект в подпути `/rem_site`. Конфигурация сборки и все локальные изображения учитывают этот префикс. Номер текущей версии, ссылка на релиз и метаданные страницы берутся из одного ответа GitHub API `/releases/latest` во время сборки без повторного использования кэша. Черновики, предварительные версии и ответы старше подтверждённой версии 5.1.12 исключаются; при ошибке API используется проверенная страница релиза 5.1.12 от 25 октября 2026 года без выдуманного URL архива. Следующий стабильный релиз принимается автоматически при новой сборке; описание 5.1.12 при этом заменяется ссылкой на изменения нового релиза. После загрузки страницы браузер использует ту же версию, не обращаясь отдельно к `main/VERSION`. Показатели GitHub также запрашиваются при сборке и имеют нейтральный fallback.

## Архитектура сайта

- `app/` — App Router, метаданные, sitemap, robots и глобальная визуальная система;
- `components/layout/` — закреплённая навигация, мобильное меню и подвал;
- `components/sections/` — самостоятельные продуктовые разделы и интерактивные сценарии;
- `components/ui/` — кнопки, карточки, статусы и общие элементы дизайн-системы;
- `components/animations/` — доступное появление блоков через Motion;
- `content/` — роли, модули, FAQ, снимки и направления развития без разметки;
- `lib/project-version.ts` — подтверждённая минимальная версия, проверка формата и числовое сравнение опубликованных стабильных версий;
- `lib/github.ts` — получение публичной информации GitHub во время статической сборки с fallback;
- `tests/` — проверки выбора версии, готового HTML и SEO-файлов.

Клиентский JavaScript используется только для интерактивных компонентов: активной навигации, каруселей, lightbox, сравнения, схемы, FAQ и формы письма. Форма не имитирует серверную отправку: после проверки она открывает почтовое приложение через `mailto:`.

## Основные библиотеки

- Next.js, React, TypeScript — приложение, компонентная модель и статическая сборка;
- Tailwind CSS 4 — базовая CSS-инфраструктура;
- Motion — анимации появления и линии этапов;
- Embla Carousel — доступные карусели с клавиатурой и свайпом;
- Lucide — основная система интерфейсных иконок;
- Simple Icons — логотипы технологий;
- ESLint — статическая проверка кода.

## Ассеты RemCard

В `public/images/remcard/` используются материалы из основного репозитория:

- `remcard-roles-5-1.jpg` — единый вход и четыре рабочих места;
- `remcard-patients-5-1.jpg` — список пациентов;
- `remcard-beds-5-1.jpg` — койки и поступления;
- `remcard-orders-5-1.jpg` — назначения и выполнение;
- `remcard-balance-5-1.jpg` — баланс жидкости;
- `remcard-workflow.svg`;
- `remcard-hero.svg`.

Главный экран и галерея используют ту же серию скриншотов **5.1.0**, что и README приложения. Версия снимков указана отдельно от текущего релиза **5.1.12**; она хранится в `content/screenshots.ts` вместе с путями и подписями. Скриншоты сняты на временных демонстрационных базах и не содержат реальных данных пациентов. Логотип находится в `public/remcardicon.png`, социальная карточка — в `public/og.png`.

Он не заменяет клинические протоколы, профессиональное решение врача, медицинскую информационную систему организации и обязательный контроль персонала. До любой реальной эксплуатации необходимы независимая техническая и клиническая проверка, тестирование резервного копирования и восстановления, а также оценка локальной сети и прав доступа.
